# 真实 Zotero 验收

已完成原生加载、实际评分通知、真实 Agent 调用和旧笔记迁移验证，详情见 [VALIDATION.md](VALIDATION.md)。以下是安装后的完整检查流程；界面操作和科学内容覆盖仍需人工验收。

1. 安装本项目 XPI，打开 Zotero 设置的 **LLM Automation Bridge** 面板，确认插件已加载。只替换文件或确认 ZIP 完整不能证明插件已加载。
2. 确认 Style 是 Extra 评分模式。已有五星论文应没有新任务。
3. 选择 llm-for-zotero 中可用的 API 多模态模型，确认其支持工具调用。核对 Prompt 是“顺序解读”独立副本，保存设置。
4. 选择一篇含真实 Figure 和 Table 的论文，把评分从 4 改为 5。关闭侧栏，选中另一篇论文；Bridge 应仍然分析原论文。
5. 在设置面板刷新任务，确认 `RUNNING`。运行中只读检查 llm-for-zotero 的 trace，确认读取的 itemId、PDF 和图像属于目标论文。
6. 完成后核对子笔记、Prompt 版本、模型、runId 和图像读取计数。逐一检查主要 Figure、panel、Table 的覆盖与内容；不能只凭 `COMPLETED` 判断科学分析正确。
7. 修改论文标题或其他 metadata，修改笔记，再同步。评分仍为 5 时不应新增任务。
8. 降到 4 再升到 5，应新增一项。默认只更新 Bridge 自己生成的笔记，人工笔记和 AI Butler 笔记保持不变。
9. 取消重新分析选项，重复降星升星，已有成功记录的论文不应再次自动分析。
10. 禁用 llm-for-zotero 后触发一项，确认保留在 `WAITING_LLM`。重新启用后应运行。同样检查 Bridge 自身禁用后没有新的模型调用。
11. 分析中关闭 Zotero后重新打开，未落盘的分析应标为 `FAILED`，无自动重复调用。已有分析正文但未保存笔记的任务只恢复保存阶段。
12. 使用只支持文本的模型，应失败且不写完成笔记。若 Agent 仅返回 caption 摘要而未读图片，也应失败。
13. 触发需要额外确认的 Agent 请求，确认 Bridge 拒绝并标记失败，不自动写入 Agent 请求的其他笔记或标签。

建议只在一台设备启用自动化。同步到这台设备的评分变化也可能触发任务，Bridge 不提供跨设备锁。
